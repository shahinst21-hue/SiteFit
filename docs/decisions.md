## Historical report snapshot decision — 2026-10-04

- D60 (accepted owner architectural direction): completed analyses and ready purchased Full Reports are persistent historical snapshots. Reopening returns the original stored report; it must not refetch providers, recalculate with current data, regenerate AI interpretation or silently overwrite it. A later check of the same property creates a new Analysis and Report version or equivalent snapshot, leaving the earlier result unchanged.
- Preserve the complete User → Analysis → Selected Property → Business Type → User Inputs → Data Snapshots → Evidence → Deterministic Metrics → AI Interpretation → Final Structured Report → Report Sections → PDF Export chain. Freeze the per-analysis selected-property representation even when the canonical property later refreshes. Record applicable analysis/retrieval/generation timestamps, source/provider identifiers, permitted normalised snapshots, evidence references, economic model version, AI provider/model, prompt version and report schema version. PDF delivery uses the same historical content.
- Determine provider permission and retention duration separately for raw responses, normalised data, derived metrics, source references and retrieval timestamps before adopting each provider. Persist only permitted representations and provenance; no permanent raw-storage assumption or automatic persistence of temporary search candidates. Resolve licensing conflicts before committing to a source; expiry must not cause silent refresh of a historical report.
- Consequence: later services must persist and validate the complete snapshot before ready, enforce the completed-report freeze, and test that reads perform no retrieval/calculation/AI work. The existing schema supplies relationships but does not implement this engine or freeze. Detailed contracts are in [architecture.md](architecture.md), [database.md](database.md) and [roadmap.md](roadmap.md). This accepted documentation decision does not authorise or implement Phase 5.
