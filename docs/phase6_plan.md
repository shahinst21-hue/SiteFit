## 2. Core analytical contract

Structured data -> deterministic metrics -> normalised subscores -> relevant comparison context -> deterministic business-specific weighting -> evidence objects -> bounded section AI -> evidence validation -> dimension result -> validated overall synthesis. Comparison definitions inform normalisation before any composition; the sequence is not an excuse to normalise without a defined cohort.

AI does not fetch facts, calculate/change scores, choose numeric weights or fill missing observations. No invented population, footfall, competitors, property facts, demand, transport, finance, failure causes or success probabilities. It selects/interprets supported business implications, opposition, alternatives and unknowns from admissible evidence.

Each dimension preserves score or suppression reason, evidence strength, conclusion, benchmark scope, supporting/weakening factors, unknowns, Evidence IDs and scoring/weight/comparison versions. A score is a 0–100 **dimension assessment**, never success/survival probability or a recommendation to sign. No overall numeric score; Early View synthesises validated dimensions and visible gating unknowns.

Numeric direction and evidence strength remain independent. The same score can have limited or stronger support; weak evidence cannot be silently treated as zero or certainty. Do not display an unauditable score. Current sources can support useful limited qualitative conclusions while all composite scores are withheld.

## 5. Versioned deterministic scoring, normalisation and comparisons

Registry and output preserve **scoring_model_version**, **business_weight_version**, **comparison_model_version**, metric/normalisation versions, operands/units/precision/source releases/effective dates, exact cohort definition/members or pinned reproducible membership, n/distribution/ties, original weights and every contributing Evidence ID. Ready reads never recalculate against current data or policies. Future recalibration creates a new analysis/model, never rewrites history.

Raw unlike units cannot be summed. Normalisation is explicitly defined per component; no arbitrary curve for a cosmetic 0–100 number. Implement percentile midrank as a **descriptive distribution position** only for a fully defined, validated cohort with at least 30 valid records, comparable units/vintage/geography, variation and acceptable missingness. Ties use (less + equal/2)/n; all-equal/invalid/too-small cohorts suppress ranking. Invert only when an explicitly reviewed favourable direction exists. Competition concentration has ambiguous direction: do not invert a count into market attractiveness.

Current residential comparison uses the pinned London OA release, matched **same local-authority area** and same source/vintage/geographic unit, excluding invalid/null/zero-area geometries and target. It is broad Census-area context, **not similar commercial locations**, current customers or a commercial-performance benchmark. Require n>=30 and >=90% valid row coverage; store exclusions and area-mix/centroid/vintage limitations. Higher resident density is only a residential-context component under an initial hypothesis; no customer-base score from it alone. Use PostGIS ST_Area(geom::geography,true), finite positive square metres and metres/CRS tests. Approximate centroid geography is explicit; ambiguous/outside/missing points suppress positional conclusions. No silent London-average fallback.

Future commercial comparator selection belongs to the later admitted inventory/catchment capability. FSA's capped mixed food list cannot produce peer percentiles or exhaustive counts; no Foursquare admission in Phase 6. TfL distances are straight-line observations around an approximate point, not walking time, a measured catchment or current access rank.

Composition formula for a complete admissible set: sum(subscore * weight)/100, rounded once to integer 0–100. **No missing-weight redistribution or zero imputation.** Require all positive-weight required components, >=90% relevant source coverage, validated favourable-direction semantics and comparator where the component requires one. Minimum independent components: Customer Base 3, Market Position 3, Access 3, Premises 3, with mandatory current-demand/time/customer fit; category inventory/competition semantics; actual journey/hour/walking evidence; and permitted-use/critical-constraint evidence respectively. The complete versioned manifest defines all positive-weight components as required in V1, so these minimum counts never permit an incomplete weighted sum. Geographic precision must fit the metric; unit/catchment/routing conclusions require verified premises point or directly applicable premises evidence, not a centroid.

This deliberately withholds the four **composite** scores on current ONS/TfL/FSA evidence. A valid residential normalised component can be retained/inspected as a narrowly named Census component, not displayed as complete demand. Missing values remain missing, observed zero remains zero, and incomplete sources cannot create an artificially high result. Tests exercise sufficient future packets synthetically without advertising those synthetic values as live.

Evidence strength is deterministic and claim-specific: absent/unrun/invalid required support -> Insufficient; partial/truncated, dated beyond its claim's freshness, centroid for micro-location, weak comparator or missing material construct -> Limited with reasons; Sufficient only for a narrow fully supported scoped proposition after every relevant predicate passes. This is not a confidence percentage and never changes the numeric score. Normalised row-count coverage is not evidence that businesses are exhaustive.

Every displayed score must answer the owner's 13-point audit: measure, contributing metrics, normalisation, comparator, original weights/basis, missingness, thresholds, Evidence IDs, version, increase/decrease drivers and prohibited inference. Suppression is a first-class stored result with concrete missing components and a useful conclusion, not an invented zero. Phase 8 can add reviewed metrics through this registry; no metric is enabled merely to fill a card.

## 6. Minimum Evidence and Data Quality Engine

The existing evidence_items UUID is the authoritative Evidence ID. Observation IDs can repeat and are not globally valid report citations. All IDs bind to analysis ownership and immutable input/snapshot lineage.

Proposed versioned envelope:

~~~text
EvidenceV1
 id; analysisId; inputId; snapshotId?; sectionIds[]
 source: provider/dataset/release/adapter; reference
 sourceClass: official_public | commercial | community_open | user
 claimKind: measured | direct_register | modelled | derived | ai_inference | user_input
 scope; value?; units?; observationBindings[]
 retrievedAt?; effectiveAt?; dateStatus
 geography: scope/CRS/locationBasis/precision/matchMethod/coverage
 quality: availability/freshnessBasis/completeness/identity/conflicts
 limitations[]; parentEvidenceIds[]; derivation?
 licence: policyVersion/permissions/notices/retention/expiry?
~~~

Source class and claim kind are orthogonal. Official provenance does not make every record measured data. The existing six SQL classifications cannot encode every combination cleanly; preserve them and add the orthogonal versioned envelope/necessary checked fields via a narrow new migration. Open commercial POI is not official data. Validated section membership needs no generic graph service.

Every material claim, including availability caveats, has supporting Evidence IDs. Source-outcome/capability evidence can support “not assessed” or “frequency was not supplied”; it does not establish physical absence. Address/business input evidence remains distinct from provider proof.

Derived evidence preserves parent IDs/operands/units/geography/method/cohort lineage. AI interpretation is labelled inference with valid parents, never self-support or cycles. Synthesis references validated section claims and underlying evidence.

IDs must exist in the same analysis/input/collection, be permitted for the tier, belong to the section packet and support claim type/scope. Reject cross-analysis, fabricated, expired/unpermitted, dangling, circular and self references. Supporting/opposing links are typed. A real UUID attached to unsupported prose is still invalid.

Data Quality outputs claim-specific allowed/blocked capabilities and reasons: dates/freshness basis, completeness, location/identity precision, conflicts and limitations. No uncalibrated quality percentage or provider-name shortcut.

Runtime validators, explicit dimension/capability policies and versioned contracts suffice. No generic ontology, lineage platform or learning infrastructure.

## 7. Bounded section AI and validated synthesis

Implementation targets the usage-based OpenAI Responses API with owner-mandated gpt-6.1-sol, strict structured outputs, store:false and address/account-free packets. Record both requested alias and actual returned model; no dated model pin is claimed. Live use requires the securely configured key and approved bounded verification budget. Standard provider abuse-monitoring retention can apply; store:false is not a zero-retention promise. Model confidence is not evidence strength. Bounded reviewed proposition selection is an explicit implementation restriction; actual value must pass live QA rather than be assumed.

~~~text
Frozen inputs + permitted source outcomes
 -> deterministic metrics/comparators and Data Quality eligibility
 -> analysis-bound Evidence objects
 -> bounded task per assessable dimension
 -> schema, reference, scope, number and policy validation
 -> persisted validated sections with AI provenance
 -> synthesis of validated sections only
 -> validated early view and frozen free report
~~~

At most three initial dimension tasks: customer context, market position, customer access. Relevant evidence only. Unavailable dimensions and premises receive deterministic evidence-linked availability plus an appropriate verification/applicability implication, not a wasted AI call or blank customer result. Premises remains not_assessed internally. Shared relevant evidence may appear in two packets; no unrestricted whole-report prompt.

Proposed SectionAnalysisV1:

~~~text
sectionId, analysisId, inputId, schemaVersion, policyVersion
availability, direction?, evidenceStrength, strengthReasons[]
presentationMeaning: favourable / trade_off / conditional / no_basis
decisionImplication: text/kind/evidenceIds[]
shortReason: text/claimKind/evidenceIds[]
claims[]: id/text/kind/scope/supportingEvidenceIds[]/opposingEvidenceIds[]
positiveSignals[], negativeSignals[], conflicts[], alternativeExplanations[], unknowns[]
recommendedChecks[]: question/decisionItResolves/evidenceIds[]
unresolvedQuestion: text/evidenceIds[]
paidContinuation: question/evidenceIds[]/approvedCapabilityKey
metricRefs[], comparisonRefs[], blockedConclusions[]
provenance: provider/model/promptVersion/generatedAt/packetDigest
~~~

Server supplies identity/version/provenance. Bound arrays/text; reject unknown fields, arbitrary HTML/URLs/unverifiable numbers. AI references metric IDs; renderer gets numeric values/dates from deterministic fields. Conditional reasoning is labelled inference. Generic checks can cite policy/input/capability evidence; local factual claims require local evidence.

presentationMeaning records the validated proposition's presentation semantics, separately from evidence strength and internal state. Validate it against the result and missingness policy; a raw model label cannot give green clearance. The renderer uses the fixed D69 colour/text mapping. It is not a score, new confidence algorithm or provider field.

The implication kind distinguishes supported_inference (including explicitly conditional hypotheses), evidence_gap_implication, verification_action and applicability_action. Primary copy prefers a result or scoped inability-to-conclude over an instruction; actions belong beneath it unless no useful supported result can be expressed. It is not inferred automatically from the state. Both implication and reason have supporting same-context Evidence IDs; inference never uses itself as evidence. Verification actions cite actual input/capability gaps and the reviewed check rule, not fictitious provider findings. Runtime policy constrains legal/financial/safety wording; “verify use” is not permission or lease advice.

Presentation budgets are proposed product rules, not confidence algorithms: decision implication <=12 words, short reason <=12, visible unresolved question <=10, continuation question <=12, overall implication <=12 and condition <=14. The old four-word overall limit is removed because it encouraged generic state headlines. Enforce character/line limits too, allow semantic repair rather than meaning-changing truncation, and test real British-English outputs at 360px/200% zoom. A material caveat cannot be removed to fit. Longer reasoning stays in validated supporting/opposing/alternative/method/limitation fields.

The section produces a continuation question tied to its actual unknowns and Evidence IDs. The server selects its destination and permitted capability from a small approved report-outline allowlist. AI cannot invent a paid capability, price, discount, availability, entitlement or a hidden finding. If no approved capability addresses the gap, omit the sales promise and show the gap; preserve access to the free evidence. A question is an investigation objective, not a guaranteed answer. Until paid capability/payment exists, contextual links open a clearly labelled non-paying report outline; no paid generation occurs.

Validation:

1. Strict schema and allowed state/direction/strength combinations.
2. Resolve each ID against actual packet/context/tier and typed lineage.
3. Match numbers/dates/identity/factual assertions to supplied fields; reject unsupported trading, demand, footfall, risk, revenue, success and routing claims.
4. Enforce quality caps, material missingness/caveats and recorded opposition. Reject implication/reason language stronger than its evidence; map unavailable/insufficient/not-assessed to supported check actions without turning missingness into a favourable/adverse finding. No “must differentiate” from a count alone, “transport supports usable access” from stops alone, or “no concern found” from an unrun check.
5. Check semantic support. Reference existence does not establish entailment. Deterministic code cannot prove all free-text inference; use bounded assertion kinds/templates, adversarial evaluations and manual factual review. An additional model judge is not the sole safety boundary.
6. At most one metered bounded repair using the same packet and validation errors, no fresh retrieval/widened evidence. Continued failure yields only honest insufficient/error result; preserve successful evidence, never call that analytical success.
7. Persist only validated interpretation; no unvalidated content/prompts/addresses/secrets in logs.

One later bounded synthesis task consumes validated section results/reference bindings/quality caps only. Its existing versioned output contains one conclusion/reason plus bounded keyUnresolvedQuestions[] with section claim and Evidence references; demand and use questions remain distinct. This is a presentation envelope, not a new workflow or lifecycle table. It cannot introduce new local facts or unvalidated evidence, and undergoes the same checks. Failure preserves sections with incomplete early view. No global bypass.

Later paid report adds bounded subanalyses then synthesis. Economics interprets separately frozen deterministic outputs and cannot alter calculations or main report.
