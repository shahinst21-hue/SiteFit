# Direct Snapshot checkout

Owner-requested change, implemented pending verification: the Full Report modal now contains the purchase purpose, one initially unchecked immediate-supply request, policy links opening in new tabs and the £29 payment action. Terms acceptance and the rights acknowledgement are recorded on that explicit purchase action; the independent immediate request remains required. Approved wording, policy versions, cancellation rights, contract formation and frozen receipts are unchanged. The separate review page redirects back to the original Snapshot modal.

An expired/missing login preserves the explicitly submitted consent in a signed, HttpOnly, SameSite=Lax ten-minute cookie, bound to the exact report and current policy. The existing exact Google/email callback URLs remain unchanged; a short-lived, allowlisted, HttpOnly auth-return cookie carries only the return path, never execution authority. Google/email login permits only the fixed checkout continuation or a validated report-resume route. After verified login, report ownership, the private trial owner and existing server-side payment/budget/consent gates are checked again before Stripe Session creation. The browser never submits a payment. Old guest reports retain the existing claim/capability transfer before checkout. No public activation, policy approval, migration or spending increase is introduced.

Missing, tampered, expired or obsolete intents do not start Checkout. Refresh/repeated requests continue through the existing durable payment and Stripe idempotency controls. No network/paid retry is added. Login/redirection is not proof of a successful payment; real card submission remains with the owner.
