# Synthesis-only controlled trial recovery

Implemented and verified through PR #90: operator-issued recovery for a trial case with exactly 17 saved sources, four received AI calls, four validated sections and a failed version-1 report. No public route or authority is seeded. The original report, dispatches, source records and trial envelope remain preserved. A separate ledger reserves only the missing synthesis against the existing US$0.65 Snapshot allowance. Full remains US$1.00 within US$4.25 trial aggregate.

The operator verifies the exact project, case, source and failed-report digests before issuing a disabled row, then enables that row only under owner execution approval. Claims, reservations and settlement lock the parent case and ledger. Only the synthesis slot is admitted; there are no source collectors or provider retries. Unknown outcomes block further dispatch. A received response is durably checkpointed before validation/finalisation and can be replayed without another request after explicit operator reconciliation.

Finalisation reuses the established evidence, spatial, section and ownership validation, writes a new version-2 Ready report, and atomically records recovery completion and binds the case to that report. The failed report stays unchanged. Normal owner-only purchase and Full fulfilment fences then apply; general public purchasing remains disabled. The original case is never reset to issued/running and its reservation only increases.

Recovery: retain the preflight encrypted/private evidence and hashes, original failed report and checkpoint. Before execution the additive migration can remain installed and disabled. After an intent, never delete/reset the ledger or refund its reservation. An ambiguous intent requires manual provider reconciliation. After a received checkpoint, rerun only the identical synthesis request for checkpoint replay and finalisation; any different digest is refused. Ready output uses existing immutable report protections. An application rollback does not remove the ledger, holds or historical records.

The real Kingston synthesis was received and checkpointed once. Finalisation then exposed a separate legacy SQL mismatch: four conservatively withheld five-minute Census estimates had null values, while the guard demanded their stored raw numeric contribution. The correction accepts only explicitly unavailable null evidence, retaining strict numeric equality for available claims and every path/source/release binding. No original evidence, AI analysis, sources or failed report is rewritten; finalisation replays the received checkpoint without AI transport.
